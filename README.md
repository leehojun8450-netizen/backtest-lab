## 데이터 파이프라인

```bash
py -3 scripts/fetch_daily.py      # 🇺🇸 미국 (Yahoo chart API)
py -3 scripts/fetch_daily_kr.py   # 🇰🇷 한국 (pykrx + FinanceDataReader)
```

**⚠️ 이 PC의 제약과 대응**
- `yfinance` / `requests` 계열은 내부적으로 curl(curl_cffi)을 쓰는데, 이 PC에서 `curl: (6) getaddrinfo() thread failed to start` 오류가 발생한다 (git push HTTPS 실패와 동일한 근본 원인)
- → 표준 라이브러리 `urllib`로 Yahoo chart API를 직접 호출해 우회한다
- → 429 대응으로 요청 간 2.5초 지연 + 지수 백오프 재시도
- 로컬 개발서버(127.0.0.1)도 차단되어 있어 **서버 아키텍처를 쓸 수 없다** → 정적 웹 + 클라이언트 연산이 강제된 설계

### 데이터 스키마 (플랫폼 규격)

TSDB 승격 시 컬럼명을 그대로 쓸 수 있도록 설계했다.

| 필드 | 의미 |
|---|---|
| `d` | reference_date — 거래일 |
| `r` | release_date — 데이터 이용가능일. ⚠️ **스키마만 존재하고 엔진은 아직 `d`로 조회한다.** 가격은 `d = r`이라 현재 차이가 없지만, 매크로 지표를 붙이기 전에 반드시 엔진을 `r` 기준으로 통일해야 한다 |
| `o/h/l/c` | 시가·고가·저가·종가 (수정주가 기준) |
| `cr` | 원주가 종가 |
| `v` | 거래량 |
| `delisted` / `delist_date` | 상장폐지 플래그 (Stage 5 전수 유니버스 확장 대비, 현재 전부 false) |
| `tax_class` | 과세 클래스 — `kr_equity` / `kr_stock_etf` / `other_etf` / `us` (아래 참조) |

현재 유니버스: **546종목** — 🇺🇸 미국 388종(2005~현재) + 🇰🇷 한국 158종(2014-05~현재, 상장폐지 33종 포함). 일봉 2,183,487개.

미국은 광역지수·섹터·해외·팩터·채권·원자재·리츠·배당·레버리지·인버스·변동성·개별주 12개 갈래, 한국은 KOSPI 시가총액 상위 개별주 + 지수·섹터·배당·해외지수·채권·원자재·레버리지·인버스 ETF로 구성한다.
도구 화면에서 **티커·종목번호·종목명 어느 쪽으로도 검색**할 수 있고, 정확히 한 종목으로 좁혀지면 그 자리에서 선택된다.

### 💰 국내 거래비용 모델 — 날짜별 세율 테이블

증권거래세는 12년간 **0.30% → 0.15% → 0.20%로 널뛰었다.** 고정값 하나로 장기 백테스트를 돌리면 과거 구간이 통째로 왜곡되므로 날짜별 테이블로 관리한다.

| 기간 | 합계 세율 |
|---|---|
| ~2019.6.2 | 0.30% |
| 2019.6.3~2020 | 0.25% |
| 2021~2022 | 0.23% |
| 2023 | 0.20% |
| 2024 | 0.18% |
| 2025 | 0.15% |
| 2026~ | 0.20% (금투세 폐지로 환원) |

근거: 증권거래세법 시행령 탄력세율(대통령령 29788·31346·33209·36001호) + 농어촌특별세법 제5조. 실무는 결제기준이라 시행일이 매매일 기준 며칠 앞서므로 매도 체결일 기준으로 보정했다.

**⚠️ 2026-08-05 정정 — 증권거래세는 개별주식에만 부과된다**

| 과세 클래스 | 대상 | 증권거래세 | 매매차익 |
|---|---|---|---|
| `kr_equity` | 개별주식 10종 | ✅ 시점별 적용 | 소액주주 비과세 |
| `kr_stock_etf` | KODEX 200 | ❌ 없음 | 비과세 |
| `other_etf` | 레버리지·인버스·해외지수 ETF 5종 | ❌ 없음 | **15.4% 과세대상 — 미반영** |
| `us` | 미국 20종 | SEC 수수료만 | 양도세 22% 미반영 |

**법적 근거**: 증권거래세법 제2조는 과세대상을 "주권 또는 지분의 양도"로 한정한다. 국내 상장 ETF는 자본시장법상 **수익증권**이라 애초에 과세대상이 아니다(비과세 특례가 아니라 대상 제외). 출처: [KRX ETF 세금제도](https://regulation.krx.co.kr/contents/RGL/03/03060105/RGL03060105.jsp)

**왜 `other_etf` 세금을 미반영하는가**: 과세표준 = Min(실매매차익, **과표기준가 상승분**) × 15.4%인데, 과표기준가 시계열을 무료로 확보할 경로를 찾지 못했다(운용사 홈페이지·증권사 HTS 단건 조회만 가능). 틀린 값을 넣느니 빼고 화면에 경고를 띄우는 편이 정직하다. 레버리지·인버스는 국내지수 기반이라도 '주식-파생형'이라 국내주식형 비과세 대상이 **아니다**.

**위탁수수료** (편도): 우대 0.0036% / 온라인 표준 0.015% / 비우대 0.15% → 낙관·기본·보수 3시나리오에 대응.
**미국 SEC 수수료**: 2026-04-04부터 매도 시 0.00206% 부활(그 이전 $0) — 날짜 분기 적용.

## 🔄 자동 갱신

```bash
py -3 scripts/update_all.py              # 변경 있을 때만 배포 (기본)
py -3 scripts/update_all.py --force      # 변경 없어도 배포
py -3 scripts/update_all.py --no-deploy  # 수집만
```

미국 일봉 → 국내 일봉 → 금리 순으로 수집하고, **실제로 새 데이터가 들어왔을 때만** 배포한다.

| 설계 | 이유 |
|---|---|
| 한 소스가 실패해도 나머지 계속 | 부분 성공을 살린다. 전부 실패할 때만 종료코드 2 |
| 변경 없으면 배포 생략 | 휴장일에 불필요한 API 호출·커밋을 만들지 않는다 |
| 로그 **append** | 하루 여러 번 돌 때(예약+로그온) 실패 흔적이 지워지면 원인 추적이 불가능해진다 |
| **회귀 방지 장치** | 새 응답이 기존보다 낡거나(최근일 후퇴) 짧으면(레코드 2%↑ 감소) **거부하고 기존 데이터를 유지**한다 |
| 종료코드 0/1/2 | 예약작업이 성공·부분실패·전체실패를 구분할 수 있게 |

**Windows 예약작업**: `backtest-lab_데이터갱신`
- 평일 **17:10** (한국장 마감 15:30 이후 + 미국 전일 종가 확정 이후)
- **로그온 시 +5분** 보충 실행 (PC가 꺼져 있어 놓친 경우 대비)
- `wscript.exe 자동갱신.vbs`로 실행 — 콘솔 창이 뜨지 않는다 (송도 대시보드와 같은 패턴)

> **⚠️ `.vbs`는 반드시 UTF-16LE + BOM이어야 한다.** UTF-8(BOM 없음)로 저장하면 WSH가 CP949로 읽어 한글 주석이 깨지고, **보이지 않는 런타임 오류 대화상자**가 떠서 작업이 영원히 `Running` 상태로 멈춘다. 2026-08-04에 실제로 겪었고 원인을 찾는 데 시간이 걸렸다. 수정할 때는 `scripts/make_vbs.py`로 재생성할 것.
- 실행 이력: `logs/update_YYYY-MM-DD.log`, 요약: `data/_update_status.json`

> **⚠️ 데이터 회귀 사고 (2026-08-04, 해결)**
> Yahoo가 같은 날 오전에는 08-03까지 주다가 저녁에는 07-31까지만 반환하는 일이 있었다. 파이프라인이 이를 검증 없이 덮어써 **배포된 데이터가 어제보다 낡아졌다.** 하루치가 조용히 사라졌고 "변경 감지 21건"으로 정상 배포까지 됐다.
> → `regression_guard()`로 차단. 데이터 제품에서 **조용한 후퇴는 오류보다 나쁘다** — 아무도 눈치채지 못하기 때문이다.

**사이트 신선도 표시**: 홈 데이터 섹션에 최근 거래일과 경과일을 배지로 표시하며, 4일 초과 시 노랑·10일 초과 시 빨강으로 경고한다. 낡은 데이터를 모른 채 쓰는 것이 가장 위험하기 때문이다.

## 도구 1 — 무한매수법 시뮬레이터

`tools/infinite-buy.html`

**전략 규칙**: 총 투자금을 N분할 → 매일 LOC(장마감 종가) 기준으로 평균단가보다 낮으면 1회차 추가 매수 → 평단 대비 +T% 도달 시 전량 매도 후 재시작.

**체결 방식 2종 선택** (2026-08-05 추가)
- **당일 종가(LOC)** — 기본값. LOC는 지정가 조건부 종가주문이라 매도 목표가·매수 기준가를 전일까지 정보로 미리 걸 수 있다. 즉 종가를 몰라도 구현 가능한 규칙이며, 이것만으로 look-ahead라 볼 수 없다. 단 **미체결 가능성은 미반영**.
- **익일 시가** — 가장 보수적. 신호일 종가로 판단하고 다음 거래일 시가에 체결.

실측상 두 방식의 **차이는 방향이 일정하지 않다** — TQQQ +16.1p / KODEX 레버리지 +2.9p / 삼성전자 −1.3p / KODEX 200 +0.8p. "종가 체결이 낙관적"이라는 통념은 데이터로 확인되지 않았다.

**경로 의존(path-dependent)** 전략이라 벡터화가 불가능하고 시간축 순차 루프가 불가피하다. 이 JS 엔진은 훗날 서버 엔진(vectorbt)으로 승격할 때 **회귀 테스트의 기준**이 된다.

**제공 지표**
- 최종 수익률 / CAGR / MDD / MDD 회복기간
- **최대 소진 회차** — 분할 탄약을 얼마나 썼는지. 무한매수법의 진짜 리스크 지표
- 완료 사이클 수 / 평균 사이클 길이 / 총 매매 횟수 / 누적 거래비용
- **단순 보유(Buy & Hold) 벤치마크 비교** — 평균 투입자본 비율 포함
- 거래비용 낙관·기본·보수 **3시나리오 병렬 계산**
- 재현 정보(가정 전문) 전량 표기

**검증 완료**
- 파이썬 독립 포팅과 전 지표 일치, Node 실행 검증 통과, 실서비스 브라우저 구동 확인, 콘솔 오류 0
- 세율 테이블 전 구간 적용 검증 (2018→0.30%, 2025→0.15%, 2026→0.20%)

**실측 결과 — 세 종목 모두 같은 패턴** (40분할 · 목표 +10%)

| 종목 | 기간 | 무한매수법 | 단순 보유 | 상승분 취득률 |
|---|---|---|---|---|
| 🇺🇸 TQQQ | 2015~2026 | +244% (MDD −27.8%) | +3,275% (MDD −81.7%) | 7% |
| 🇰🇷 KODEX 레버리지 | 2014~2026 | +55.9% (MDD −52.2%) | +634.9% (MDD −68.4%) | 9% |
| 🇰🇷 삼성전자 | 2014~2026 | +98.6% (MDD −24.4%) | +709.2% (MDD −45.2%) | 14% |

세 경우 모두 **분할 40회를 전량 소진**했다. 이 전략은 수익 극대화가 아니라 변동성 완화 장치다.

**국내 비용 구조의 특징**: 삼성전자 기본 시나리오에서 거래세 27.5만원 vs 수수료 3.2만원 — **거래세가 수수료의 8.6배**. 국내는 매도세가 지배적 비용이라 회전율 높은 전략에 특히 불리하다.

## 도구 2 — 포트폴리오 시뮬레이터

`tools/portfolio.html`

여러 자산을 정한 비중으로 담고 주기적으로 리밸런싱했을 때의 성과를 검증한다. 프리셋 6종(국내 3·미국 3), 자산 무제한 추가, 적립식(매월 납입) 지원.

**핵심 질문**: *"리밸런싱이 정말 이득이었는가"* — 6개 주기(하지않음/연1회/반기/분기/매월/밴드±5%p)를 **거래비용까지 반영해 한 표에 나란히** 계산하고, 방치 대비 손익·낙폭·변동성 변화를 문장으로 판정한다.

**실측 결과 — 통념과 반대**

| 포트폴리오 | 리밸런싱 없음 | 연 1회 | 판정 |
|---|---|---|---|
| 🇺🇸 SPY 60 / IEF 40 (2015~) | **+208.8%** (MDD −22.6%, 변동성 12.2%) | +164.4% (MDD −21.3%, 변동성 **10.2%**) | 리밸런싱이 수익을 **44%p 깎고** 변동성을 2%p 낮춤 |
| 🇰🇷 KODEX200 60 / TIGER나스닥100 40 (2015~) | +553.1% (MDD −29.0%) | +594.5% (MDD **−34.3%**) | 수익은 늘었지만 **낙폭은 깊어짐** |

즉 리밸런싱은 **수익 장치가 아니라 위험 장치**이며, 그조차 항상 성립하지 않는다.

**주의 — MDD 부호**: MDD는 음수라 −29% → −32%는 '깊어진' 것이다. 개발 중 이 부호를 뒤집어 *"3.3%p 줄었습니다"*라고 잘못 출력한 버그가 있었다(2026-08-04 수정). 두 도구 모두 얕아짐/깊어짐을 명시적으로 분기하도록 고쳤다.

## 도구 3 — 레버리지 변동성 끌림 계산기

`tools/volatility-drag.html`

레버리지 ETF의 성과가 "기초 수익률 × 배수"와 왜 다른지를 **단계별로 분해**하고, 계산한 이론값을 **실제 ETF와 대조**해 모델 정확도까지 표시한다. 비교 쌍 9종(미국 6·국내 3).

**손실·이득 분해 사다리**: 순진한 기대 → ① 일일 재조정 효과 → ② 운용보수 → ③ 차입금리+스프레드 → ④ 실제 ETF

**모델 검증 결과** (2015~2026, 운용보수 공시치 + 스프레드 0.5%)

| 비교 | 이론 | 실제 | 오차 |
|---|---|---|---|
| QQQ → TQQQ (3배) | 3,505 | 3,375 | **+3.8%** |
| QQQ → QLD (2배) | 2,014 | 2,001 | **+0.7%** |
| SPY → UPRO (3배) | 1,424 | 1,347 | +5.7% |
| SPY → SSO (2배) | 907 | 888 | +2.1% |
| IWM → TNA (3배) | 189 | 179 | +5.8% |

**⚠️ 차입금리를 빼면 이론값이 2배로 부풀려진다** — TQQQ 기준 이론값이 3,505(금리 반영) vs 6,308(운용보수만) vs 7,039(비용 0). 대부분의 레버리지 백테스트가 이 항목을 누락한다.

**금리 데이터**: FRED(DFF)는 이 PC에서 ConnectionReset으로 차단되어, 이미 검증된 Yahoo 경로로 **^IRX(미국 13주 국채수익률)**를 대리지표로 쓴다. 국내 원화 조달금리는 확보 경로를 찾지 못해 **미반영**이며(그래서 KODEX 레버리지 오차가 +38.3%로 큼), 도구가 이 사실을 직접 표시한다.

**⚠️ 개념 정정 — "변동성 끌림"은 항상 손실이 아니다**

일일 재조정은 양날의 검이다. 한 방향 추세가 강하면 복리가 가속되어 배수보다 **더 벌고**, 등락이 반복되면 깎인다.

| 사례 | 순진한 기대 | 일일 재조정 효과 |
|---|---|---|
| QQQ → TQQQ (2015~2026 상승장) | +1,882% | **복리 가속 +5,057p** |
| IWM → TNA (러셀2000, 변동성 큼) | +552% | **변동성 끌림 −270p** |

TNA는 기초가 +552% 올랐는데 실제 3배 상품은 **+79%에 그쳤다.** 개발 초기에 "끌림=항상 손실"로 전제해 이득 구간을 손실로 표시하는 오류가 있었고(2026-08-04 수정), 지금은 부호에 따라 **복리 가속 / 변동성 끌림**을 분기해 표시한다.

## ⚠️ 공개 저장소와 이 폴더의 차이

배포되는 것은 `index.html` · `tools/` · `data/` · `.nojekyll` · `README.md` **뿐**이다. `scripts/`(수집·배포·회귀방지)와 `자동갱신.vbs`, `logs/`는 **로컬에만 있고 공개 저장소에 없다.** 따라서 외부에서는 데이터 수집·검증 로직을 감사할 수 없다. 공개 여부는 별도 판단 사항이다.

## 🤝 Gemini 자율 협업 (API 키 있을 때)

```bash
py -3 scripts/gemini_collab.py --check          # 키·연결 점검
py -3 scripts/gemini_collab.py                  # 미처리 의뢰서 전부
py -3 scripts/gemini_collab.py REQUEST-001.md   # 특정 건만
```

`collab/REQUEST-NNN.md`를 읽어 **의뢰서에 적힌 raw URL의 실제 본문을 첨부**한 뒤 Gemini API에 보내고, 회신을 `collab/RESPONSE-NNN.md`로 저장한다.

| 설계 | 이유 |
|---|---|
| **URL이 아니라 본문을 첨부** | API는 브라우징을 못 한다. URL만 주면 '읽은 척'하는 답이 온다 |
| `urllib` 직접 호출 | 이 PC는 curl 계열이 죽어 있어 SDK·requests를 못 쓴다 |
| 시스템 프롬프트에 금지사항 주입 | 추측 금지·코드 금지·수치 계산 금지·기지(旣知) 한계 재지적 금지 |
| 회신 헤더에 "검증 전" 명시 | 자동 생성 의견을 사실로 착각하지 않게 |
| 키는 **repo 밖** 보관 | 환경변수 또는 `%LOCALAPPDATA%acktest-lab\gemini_key.txt`. `scripts/`는 배포 대상이 아니라 공개되지 않음 |

**⚠️ Gemini 웹앱으로는 자율 협업이 원리적으로 불가능하다** — 웹앱은 사람이 프롬프트를 넣어야만 동작하고 GitHub 쓰기 권한도 없다. API만이 우리가 먼저 호출할 수 있어 무인 실행이 된다.

## 설계 원칙

1. **모듈 승격 원칙** — 지금 만드는 것은 임시 MVP가 아니라 플랫폼 v1의 정식 모듈. 스키마·엔진 로직을 처음부터 플랫폼 규격으로
2. **검증 생략 불가** — 마찰비용 3시나리오는 무료 도구에도 기본 탑재. 비용 가정을 제거한 결과는 공개·유통 불가
3. **벤치마크 없는 성과는 무의미** — 모든 결과에 단순 보유 비교를 강제 표시
4. **주장이 아니라 실측** — 문구도 계산된 값에 따라 분기. 손실 구간에서 "이익 대비 비율"을 말하지 않는다
5. **벤치마크에도 같은 비용** — 2026-08-05 수정. 전에는 단순보유가 가격비만 계산해 비용 0이었다. 비용 있는 전략과 비용 없는 벤치마크를 비교하면 그 자체로 불공정하다
6. **적립식은 TWR로** — 2026-08-05 수정. 월 납입금을 평가액에 더한 뒤 그 증감률로 MDD를 재면 외부 현금유입이 수익처럼 섞인다. 단위가 기준(TWR)으로 MDD·변동성·CAGR을 계산하고, '납입원금 대비'는 별도 표기
